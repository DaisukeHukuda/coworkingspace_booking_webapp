  `design_handoff_torch_booking/PROMPT.md`（全9画面のハイファイ仕様・デザイントークン）と `TORCH予約システム.dc.html`（参照モック）
- 方針: **見た目だけを差し替えるリスタイル**。機能・URL・フォームフィールド名・リダイレクト・DB操作・メール送信は1ビットも変えない

## PROMPT.md からの意図的な逸脱（2026-07-26 福田さん確認済み）

1. **回数券の残回数表示（§4-2「残り 8 回分」）は実装しない** — 残数管理が未実装のため（ステップ⑥で実装時に追加）
2. **LINE導線（§4-7）は実装しない** — LINE公式アカウントのURLが未定のため（URL決定後に追加）
3. **URLは現行のまま** — 承認待ちは `/admin/requests`（PROMPTの `/admin/pending` 例には従わない）。リクエスト一覧は `/admin/requests/all`
4. **メール文面は5カード** — PROMPTは4カードだが、現行機能どおり「キャンセル通知（スタッフ宛）」を含む5種を編集可能のまま維持（スタッフ宛スタイルで表示）
5. **「次回のご利用」カード（§4-3）** — 実データ（本人の直近の確定予約・今日以降で最も近い1件）で表示。無ければ非表示（PROMPTどおり）
6. **バリデーションは現行ロジックのまま** — 表示文言のみデザインのトーンに合わせて更新可（挙動・リダイレクトパラメータは不変）

## テストの取り扱いルール

- 機能的アサーション（ステータスコード・リダイレクト先・DB状態・件数・メール内容）は**変更禁止**
- UI文字列のアサーションのみ、新デザインの文言に合わせて**最小限**更新可。テストの追加・削除はしない（件数152件を維持）
- 互換のため**維持するマークアップ/クラス名**（テストが依存）:
  - 予約ドット: `cal-dot dot-pending / dot-confirmed / dot-declined`（形・色はCSSで§4-4どおりに変える。凡例には各クラスちょうど1回ずつ）
  - 停止日マーク: `<span class="mark">停</span>`／満席マーク: `<span class="mark mark-x">×</span>`（見た目はCSSで調整）
  - ダッシュボード: `dash-warn` クラス・「承認待ちのリクエストはありません」「承認待ちを開く」「同期無効」「直近エラーなし」の文言
  - 承認待ち警告バッジの文言「Square側で埋まった可能性」（記号は△に変更可）
  - 「この日はSquare側で空きがありません」「×の日はSquare側の空きがありません」「受付を停止しています」等、テストが参照する文言は原則維持
